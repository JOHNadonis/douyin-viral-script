# 45 秒三段式拍摄脚本规范

**这是三条产线里最实战的一条。跟前面两条的区别：它输出的不是口播稿，是拍摄脚本——每一句文案都必须配一个画面指令。**

## 为什么必须配画面

之前写的口播稿，只有字。但实际拍的时候，剪辑师会问：这句话放什么画面？

这套框架的答案是**逐行配对**。用户的原始框架图长这样：

| 结构 | 时间 | 文案 | 画面 | 作用 | 目的 |
|---|---|---|---|---|---|
| 开头 | 0-5秒 | 卫生间霉斑刷不掉的，看这里 | 痛点近景展示，卫生间霉斑，可以适当调色 | 痛点阐述 | 留人：2s出 |
| 开头 | 0-5秒 | 尤其是到了冬天…怎么刷都刷不掉 | 继续展示卫生间霉斑的场景 | 引入场景 | 留人：5s完成 |
| 中段 | 5-30秒 | 直到朋友给我推荐了这款霉卫士 | 产品镜头 | 介绍产品 | 商品点击 |
| … | | | | | |

**没有画面的行是不合格的。** 只有「行为指引」那一行可以写「—」，因为那时候指着小黄车就行。

## 整体逻辑（图3）

```
短视频 = 模型框架
         ├ 开头（0-5秒）→ 留下用户 → 与「我」（消费者）有关
         │    └ 强痛点/爽点/痒点/对比 + 强画面 → 目标人群清晰
         │
         ├ 中段（5-30秒）→ 说服用户 → 购买理由
         │    └ 真实场景 + 解决方案 + 证据佐证 + 购买理由
         │
         └ 结尾（30-45秒）→ 转化用户 → 临门一脚
              └ 行为引导
```

三个目标一句话：**开头留人、中段说服、结尾转化。**

45 秒比 60-90 秒紧得多，所以：
- 开头 2 秒内必须出钩子，5 秒完成
- 中段 25 秒要塞进「场景+方案+佐证+理由」，通常 2-4 个购买理由
- 结尾 15 秒两步走：先拉回人群，再指路

## 一、开头四类钩子（0-5 秒）

按产品特性选，不是随便挑。

### H1 痛点型开头

模板：`[痛点人群]+[痛点场景]，[产品]千万别乱买`
例子：**头发一吹就炸毛的人，护发精油千万别乱买**
画面：手里拿着产品，捏着自己炸毛的头发（没有真人出镜，用照片代替）
适合：用户痛点明确 + 解决方案清晰
原理：第一秒点名人群，让人对号入座

### H2 爽点型开头

模板：`[结果爽点]！！！`
例子：**这双发黄的白鞋，居然洗这么干净！！！**
画面：手里拿着干净的小白鞋，然后画面贴一张发黄的小白鞋照片
适合：强视觉冲击产品
原理：先给结果，靠反差抓眼

### H3 强冲突开头

模板：`左边用了，右边没用，[效果差得很明显]`
例子：**左边用了，右边没用，头发毛躁度真的差很多**
画面：左右贴图效果对比
适合：具备很好效果对比的产品
原理：并置对照，最直观

### H4 痒点型开头

模板：`你以为[常识判断]，其实[真相]`
例子：**你以为洗面奶越干净越好？其实油皮更容易踩这个坑**
画面：油皮脸红的贴图
适合：强说服型产品，需要长向解说
原理：制造认知缺口，勾人听下去

## 二、中段七种购买理由（5-30 秒）

中段的功能只有一个：**给足「凭什么买」的理由。**

不要只放一个理由。实测框架里，中段至少要「真实场景 + 解决方案 + 证据佐证 + 购买理由」四个动作，拆开就是下面这些。

### R1 场景代入
模板：`一到[季节/场景]，[具体处境]，回来[一堆麻烦]`
例子：一到夏天，我家小孩楼下小区走一圈，回来一大堆包
画面：贴腿部图，头上蚊虫叮咬的画面
适合：用户痛点明确 + 解决方案清晰

### R2 过程实测
模板：`往上一涂，立马[可见变化]`
例子：往上一涂，立马变亮光泽
画面：使用过程
适合：无需剪辑就能展示过程的产品

### R3 前后对比
模板：`左边用了，右边没用，[差异]`
例子：左边用了，右边没用，头发毛躁度真的差很多
画面：左右贴图效果对比

### R4 成分资质
模板：`这款[产品]成分[干净/安全]，没有[可疑成分]`
例子：这款毒卫士成分干净，没有任何刺激性成分
画面：产品图片，展示 logo、产品配方
适合：产品资质齐全

### R5 痛点答疑
模板：`最开始的时候，我还在想是不是[质疑]，结果真的很[有效]`
例子：最开始的时候，我还在想是不是智商税？结果真的很少有蚊虫叮咬了
画面：小孩开心的画面
适合：用户痛点型产品

### R6 品牌背书
模板：`这款产品是[品牌]，他们做了[年限]的[品类]，[资质/渠道]`
例子：这款产品是莹特家的，他们做了三十年的驱卫洁用品，全部是用于出口，经过XX检验
画面：资质截图提示
适合：背书资源丰富

### R7 优惠机制
模板：`现在[品牌]为了冲[销量/活动]，原价[原价]的[品]，[现价]就可以[到手数量]`
例子：现在毒卫士为了冲销量做活动，原价29元一瓶，49元就可以买三瓶了
画面：优惠照片

## 三、结尾两步（30-45 秒）

### E1 引入人群
模板：`如果你的[场景A]、[场景B]也老是[痛点]，怎么[做]都不行`
例子：如果你的厨房、卫生间、卧室也老是潮湿发霉等，怎么刷都刷不掉
画面：场景图
作用：把人拉回自己的处境，确认「说的就是我」

### E2 行为指引
模板：`下面是视频同款，赶紧点击下方的小黄车试试试`
画面：—（此时指着购物车即可）

**E1 不能省。** 直接跳到「点小黄车」会显得突兀，先重新点一次人群，转化才顺。

## 四、写完怎么验

```bash
python scripts/dvt.py check45 --script /path/s45.json --range 180-260 --require-cta --strict
```

会查：
- 总字数是否在区间（45 秒大约 180-260 字）
- 开头/中段/结尾三段是否齐全、顺序对不对
- **每一行是否配了画面**（NO_VISUAL）
- 有没有元叙述（这期讲完/本期/今天讲）
- 有没有行为指引

### 多商品批量校验

一次写多条时，在 `rows` 里给每行加 `product` 字段，校验器会**自动按商品分组，逐条独立算字数**：

```json
{"rows": [
  {"product": "儿童牙膏", "seg": "开头", "text": "...", "visual": "..."},
  {"product": "椰子水",   "seg": "开头", "text": "...", "visual": "..."}
]}
```

输出会逐条列出：

```
儿童牙膏          9 行   232 字  ✓
早餐组合          9 行   235 字  ✓
鱼皮花生          9 行   211 字  ✓
椰子水            9 行   272 字  ✗ 1

   [椰子水] TOTAL_LONG(272>260)
```

**不带 `product` 就当成一条脚本合并算字数**，四篇一起算就会误报超长。这是 v1.2.1 修的坑。

### 从 Excel 回读要注意

Excel 里「结构」「时间」列是纵向合并的，**合并后只有首格有值，其余是 None**。把 Excel 读回 JSON 再校验时，如果直接读会误报「结尾不在最后」。

`check45` 已内置回填：`seg`/`time` 为空时自动沿用上一行的值。所以直接把导出的 Excel 读回来校验也能过。

`NO_VISUAL` 报错说明你只写了字没写画面，那还是口播稿，不是拍摄脚本。

## 五、跟另外两条产线怎么配合

| 产线 | 输出 | 什么时候用 |
|---|---|---|
| 45 秒三段式（本文件） | 文案+画面逐行脚本 | **要开拍的时候用这条** |
| 60-90 秒带货稿 | 纯口播 | 只给人念，或做混剪配音 |
| 费曼知识稿 | 纯口播 | 讲概念、AI 科普 |

三个可以叠。比如：先用 45 秒框架搭结构（保证画面齐全、节奏正确），中段的「解决方案」那一句用费曼的手法写（加类比、翻术语），开头用东方甄选的固定收尾话术。

**45 秒框架管骨架，费曼管讲解质量，东方甄选话术管味道。三者不冲突。**

## 六、自检五问

1. 每一行都有画面吗？（除了行为指引）
2. 开头 2 秒内出钩子了吗？钩子类型和产品特性匹配吗？
3. 中段有几个购买理由？只有一个就是单薄
4. 结尾先点人群再指路了吗？
5. 总字数超 260 了吗？超了念不完 45 秒
